# 0.1.1 固件审阅修复计划

依据工作区《审阅报告-固件.md》（2026-11-17），仅修改固件仓库。修复分支 `codex/firmware-review-0.1.1`，版本由 0.1.0 升为 0.1.1。0.1.0 的源码与镜像归档保留，发布新版本独立目录，不覆盖旧包。

## 实施顺序

1. 数据完整性与生命周期：FW-01/02/03/04/05/11/14/15/17。BLE 通知独立拥有数据、异步分片；串口表统一加锁；会话重置和 AP 表均由 CPU1 DAP worker 管理；TCP 与 BLE 使用会话代号隔离旧响应。
2. 协议与 SWD：FW-06/07/08/09/12/13。修正 APSEL、精确解析 SWJ 整数、严格校验数组；明确块上限；批量内存访问并处理 TAR 自增回绕；限制 GPIO、清理 SPI 生命周期。
3. USB 与 OTA：FW-10/16/25/26。USB HID 发送调度到 TinyUSB 上下文，发送与 OTA 等待移出总线锁；USB 授权只开放 USB OTA，物理按钮/控制台按链路授权；锁内状态快照、可配置超时和端口。
4. 诊断与工程化：FW-18～24/27～30。修复定时器、日志、配置响应和控制台范围，补充测试与限制说明，构建并归档 0.1.1 源码及完整烧录镜像。

## 验证与验收

- 原生 C 回归：真实 `dap_server.c` + cJSON、可替换 probe 后端，覆盖 4096 字节写入、越界拒绝、APSEL/版本、SWJ 大整数、最大响应；模拟 SWD 传输验证非对齐访问与 1 KiB TAR 边界。
- ESP-IDF 6.1 构建、分区/容量校验、esptool 镜像校验、ZIP 与逐文件 SHA256 校验。
- 必须另做硬件验收：BLE 压力/重连、USB/WiFi 烧录与 OTA、40 MHz TCP 断连、SPI2 示波器频率与采样。没有执行硬件测试时明确保留为待验收，不以静态检查替代实测。
- 安全边界：物理按钮允许的无线升级窗口内，同链路客户端仍需被信任；不宣称 SHA256 等同签名认证。

报告结论逐项复核后记录在本文件；不成立或描述不准确的项会说明依据。

## 已验证的修复

- FW-02/06/07：字节写直接解析到字节缓冲，所有数组越界/非整数/非法元素整体拒绝；APv1 使用未移位 APSEL，同 AP 重用 handle，APv2 明确拒绝；SWJ 从原始十进制文本解析到 256 位，另支持十六进制字符串，避免 double 舍入。
- FW-08：响应上限按 64 字节头预算、每 uint32 最多 11 字符/byte 最多 4 字符计算，现为 1856 字/5104 字节。原报告称 5056 字节响应必溢出不成立：5056×4=20224，小于 20480 扣头预算；真实问题是文档不一致及 AP multiple 未限制响应长度。原实现 FW-09 读循环每 4 字节一次，并非每字节一次，仍可通过批量访问提速。
- 首组验证：`python tests/run_native.py`，8 项协议回归通过（包含多个边界子场景），原生 C 使用 `-Wall -Wextra -Werror`；尚未代表硬件测试通过。
